## Overview

This study utilizes a single-cell RNA sequencing dataset of the ferret (_Mustela furo_) and a single-nucleus RNA sequencing dataset of the human to investigate the validity of the ferret species as a model for early pancreatic development, specifically in the ductal and acinar pancreatic cell types. The goal of this analysis is to gather pancreatic cell types from the human dataset and apply them to the ferret scRNA-seq dataset, then create pseudotime lineages in both species and compare the gene regulatory programs through early differentiation. This is made possible through the `Seurat` integration toolkit, the `slingshot` and `fitGAM` R packages, and the `CellRank` python package to explore a wide variety of computational lineages through captured timepoints.

Please contact [christopher.2.hill\@cuanschutz.edu](mailto:christopher.2.hill@cuanschutz.edu) with any questions.

## What This Repository Does

This repository provides a complete pipeline for the ferret-human scRNA-seq/snRNA-seq integration and computational lineage tracing. Specifically, it:

-   Visualizes the ferret scRNA-seq and human snRNA-seq datasets in UMAP space and validates the human cell type naming scheme
-   Performs `Seurat` CCA Integration between the two datasets using PCA embeddings and renames the ferret cells according to a k-Nearest Neighbors (k=10) strategy
-   Analyzes the cell type renaming strategy and unbiasedly extracts marker genes from the two species to valiate the integration
-   Recreates PCA embeddings for the original human snRNA-seq dataset using the author's published steps
-   Creates a series of computational pseudotime lineages starting from a progenitor population and moving through ductal or acinar progenitor, immature, and maturing cell types
-   Maps the ferret genes to the human gene list using a curated ortholog file and subsets the two experiments to only use common genes
-   Runs `fitGAM` on the computational lineages to determine the genes most associated with the two ductal/acinar lineages for the two species
-   Calculates terminal lineage fates using `CellRank` and correlation scores of the most associates gene lists and compares them between the species
-   Generates KEGG pathways highlighting ductal or acinar specific differentiation pathways that are shared between the species
-   Creates all plots featured in the manuscript

## Repository Structure

### `figures`

All of the figures generated from this analysis pipeline and included in the final manuscript are housed in this location. The prefixed number for each figure corresponds to the scripts in `src` that was used to create the plot.

### `fitgam_objects`

The `rda` files that were generated from running the fitGAM function on the saved `SingleCellExperiment` and `Seurat` object files for each species in the two lineages, specifying the cell type, and start and end cluster that were run with `slingshot` in the downstream `09_ferret_lineages.Rmd` and `10_human_lineages.Rmd`. These `SingleCellExperiment` and `Seurat` object files are not saved here to conserve space, but both can be easily regenerated by running the `07_save_for_fitGAM.R` script. 

### `pseudotime_objects`

The `csv` files containing lineage weights and pseudotime values that were generated using the same `Seurat` objects as well as the start and end clusters for the `fitGAM` calculations. These values were extracted from the calculated `slingshot` computational lineages, and saved along with the `Seurat` objects converted to `.h5ad` file format to move the analysis from R into an python environment. This was necessary as the downstream `CellRank` package does not have a dedicated R implementation, so everything needed to be ported over into a different IDE. The `h5Seurat` and `h5ad` files that were needed for the downsteam `12_cellrank_terminal_fates.py` and `13_correlation_scoring.py` scripts were not uploaded here to conserve space, but both can be easily regenerated by running the `11_save_for_cellrank.R` script.

### `src`

The directory in which all of the source scripts that were utilized in this analysis are located. Most files contain `_helpers.R` files that include a series of helper functions specific to that step, and there is also a `common_setup.R` function that is run prior to all of the R scripts to load in files, directories, and color palettes. More specifically for each of the files located in this directory:

#### `01_dataset_visualization.R`

As an initial overview of the datasets we have available, this script loads in our scRNA-seq ferret dataset and the published snRNA-seq human dataset. The day attribute is used from the ferret dataset (days 22, 24, 28, 35) to visualize the population distribution in UMAP space and gene expression patterns across the four collection windows in a heatmap. Similarly, the post-conception weeks (PCW) attribute from the human dataset is used to visualize the population distribution in UMAP space, and gene expression patterns are calculated across the cell types in a heatmap and a barplot to view how it changes across the 3 collection windows.

The helper `.R` file for this step contains a barplot plotting helper function and logic to extract the differentially expressed genes using `FindAllMarkers` and plot them on a heatmap.

#### `02_integration.R`

After the datasets have been loaded in, we calculate the ferret-human integration using the `Seurat` CCA-Integration method to merge the datasets in UMAP space using calculated PCA embeddings. Upon integration, the combined dataset is visualized in UMAP space by species to see how the two datasets overlap, before a k-Nearest Neighbors strategy with k=10 is used to label each ferret cell with the majority cell type of the 10 nearest human cell types. Upon performing this labeling, the merged dataset is again visualized in UMAP space to determine the effectiveness of the relabeling, and then each species separately to get a general idea of the cell type numbers for the ferret dataset.

The helper `.R` file for this step contains an ortholog function that converts the ferret gene names into human gene names where possible, as well as the main integration calculation helper function that only uses the genes included in both datasets for downstream Normalization, Scaling, and PCA calculation. Also included is a `subset_anova_genes` helper function to aid in removing genes that would be highly species-specific and biasing, and the final kNN mapping helper that relabels all of the ferret cells with the majority cell type from the human neighbors.

#### `03_ferret_renaming.R`

With the ferret cells now mapped with their new human kNN celltype, we perform a series of cleanup steps here before the downstream analysis continues. Contained in this file is logic that renormalizes, scales, and calculates seurat clusters and PCA/UMAP embeddings to create a visualization more similar to the one we started with in step 1 for the ferret dataset. We visualize this UMAP projection then calculate clustering at a higher resolution of 7. Upon doing so, all cells in each cluster are renamed with their majority within these subpopulations, and the clusters are then recalculated with a resolution of 0.8. The final step is a manual renaming of 4 clusters to be completely of one cell type (Alpha, Beta, Delta, Ductal immune), and then a series of visualizations are created in UMAP space to trace these steps. Finally, a differential expression (DE) heatmap is calculated to validate that these populations have unique gene expression patterns as we did with the original human `Seurat` object.

#### `04_remake_published_object.R`

The downstream pseudotime computational lineages require the original PCA embeddings of the human dataset, which were not available in the author's published `Seurat` `.rds` object. This script then attempts to regenerate these embeddings using the raw barcode, feature, and matrix objects for each of the six samples included in the human snRNA-seq dataset. A `Seurat` object is made per sample, and all six `Seurat` objects then merged, SCTransformed, and scaled as per the authors methods. Only the cells present in the final published object were subset, and then a series of SCTransform and PCA/UMAP embedding calculations were performed before visualizing the final projection as sufficient for downstream analysis. 

#### `05_create_subset_species_objects.R`

Similar to what was done in the integration step, all downstream gene regulatory program analysis needed to be done on the same set of genes per species. As a result, this script reads in our two species objects and maps the ferret genes to the human orthologs where an entry was available. The human dataset requires the Ensembl ID's to be converted into their gene symbols as well to match the ferret dataset and it's newly converted names, so a `biomaRt` instance is created and converted before standard normalization and scaling processing steps was performed on the two datasets. Finally, the two gene lists from the specis are intersected, and only the genes present in kept in the two `Seurat` objects. These genes will also be the complete set of genes serving as the background for the eventual KEGG analysis, so we save those to a `csv` file for later.

#### `06_celltype_validation.R`

After the ferret dataset has been renamed and the two `Seurat` objects have been subset to include common genes, we investigate celltype specific gene expression to see if it is comparable between the species. To do so, the datasets are loaded in and marker genes are calculated per cell type via `FindAllMarkers`. The genes that result are ranked by `abs(avg_log2FC)`, and a large enough sample size (n = 2000) is taken from both species in order to get 100 shared genes that are have high log2FC values in the two species. Expression data is extracted for these gene sets using our helper differential expression heatmap function, and only genes that have scaled Z-score expression values > 2 in the ferret and human datasets are extracted. This final gene list is plotting once more with the DE heatmap helper and cell type specific marker genes can be observed as unbiasedly pulled out and specific to the cell type we would expect.

The helper `.R` function contains this validation differential expression heatmap function that is synonymous with the DE heatmap function from earlier analysis steps but contains overflow prevention that can occur in this step.

#### `07_save_for_fitgam.R`

In order to run `fitGAM` on the identified pseudotime slingshot trajectories, the `Seurat` objects and corresponding `SingleCellExperiment` objects that are calculated from `slingshot` need to be saved to be input into the function correctly. To do so, our `run_slingshot_subset` function is written to take in a `Seurat` object, the name of it's clusters (`seurat_clusters` or `Leiden_cluster`), and the start/end clusters. The `slingshot` function is run with the first 15 PCs in the `Seurat` object embedding, and the `SingleCellExperiment` and `Seurat` object subset to just these clusters of interest are saved to `.rds` files for the next step of actually performing `fitGAM`.

#### `08_run_fitgam.R`

With the files saved, we can now utilize the functions from the `tradeSeq` R package to identify genes associated with the pseudotime lineages in the two species. To do so, our `run_tradeseq_pipeline` function reads in the saved `Seurat` and `SingleCellExperiment` objects, extracting the cells involved in the pseudotime trajectory from the object and finding variable features before running the `evaluateK` function. We determined a value of 7 for K fit the four trajectories the best, so that value, the psuedotime values, and cell counts and their weights are all fed into the `fitGAM` function with the final output saved to `.rda` files.

#### `09_ferret_lineages.Rmd`

The first of two R markdown files in this analysis pipeline, we take the ortholog mapped and subset ferret `Seurat` object and calculate pseudotime computational lineages to have in hand when we compare to the human lineages. In these trials, we identify a ductal lineage from clusters 9 to 0, and an acinar lineage from clusters 9 to 10, subset the clusters associated with these ductal or acinar specify cell types, then run `slingshot` with the top 15 PCs to get the pseudotime curves. This with the loaded in `tradeSeq` `fitGAM` models is used to test which genes are most significantly associated with each lineage in the two cell type trajectories. For each lineage, we compute a UMAP plot of the pseudotime curve and a heatmap of the significant differentially expressed genes along the trajectory.

#### `10_human_lineages.Rmd`

The companion R markdown to the ferret trajectory in this analysis pipeline, we again calculate pseudotime computational lineages to compare to the ferret lineages. In these trials, we identify a ductal lineage from clusters 10 to 19, and an acinar lineage from clusters 10 to 2, subset the clusters associated with these ductal or acinar specify cell types, then run `slingshot` with the top 15 PCs to get the pseudotime curves. This with the loaded in `tradeSeq` `fitGAM` models is used to test which genes are most significantly associated with each lineage in the two cell type trajectories. For each lineage, we compute a UMAP plot of the pseudotime curve and a heatmap of the significant differentially expressed genes along the trajectory. All of these plots are compared alongside the ferret equivalent file to assess the quality of the computational trajectories.

The helper `.R` function for these two markdown files contains dataset specific configuration functions to supply the correct metadata columns per species, orthlogy and query gene helper functions to find cluster markers and map them to the human gene list for the ferret dataset, the core logic for running `slingshot` on the `SingleCellExperiment` object and embedding the trajectories onto the UMAPs, and and series of plotting helpers for the violin, UMAP, and heatmaps looking at the expression of DE genes.

#### `11_save_for_cellrank.R`

The `Seurat` and `slingshot` `SingleCellExperiment` objects next need to be processed with `CellRank` to calculate terminal cell fate probabilities, which requires conversion of the file types so they can be imported into python. All of the same trajectories from the previous step are recalculated with the same start/end clusters and subsetted objects that focus on the ductal or acinar cell types, and the resulting pseudotime and cell weight values are written to `.csv` files while the objects are written into `.h5Seurat` files and converted into a `.h5ad` AnnData file format. These files are now ready to be loaded into a python environment in another IDE.

#### `12_cellrank_terminal_fates.py`

Now in python, this script runs `CellRank` terminal cell fate mapping analysis on each of the four species/lineage combinations (ferret acinar/ductal, human acinar/ductal). For each computational lineage, the `.h5ad` AnnData and pseudotime and cell weight `.csv` files are loaded in with the correct lineage extracted from the `slingshot` objects. To match the degree of differentiation between the two species, the human pseudotime was capped at manually tested thresholds so the resulting terminal cell fate calculations were comparable. A k-Nearest Neighbor graph with a PseudotimeKerneal transition matrix was created, and a GPCCA estimator with manually set terminal cell fates was fit on the datasets. From there, a series of transition projections, fate probability maps, circular projections, and UMAPs colored by fate probabilities for computational lineage driver genes for each terminal state are plotted, and `.csv` files are created of these computational lineage drivers. Finally, the two gene lists of interest, the `well-associated` and `ferret-specific` marker gene panels were plotted.

#### `13_correlation_scoring.py`

Still in python, this script loads in the species specific computational lineage drivers and scales their correlation scores by their 1st and 99th percentile magnitude and clips them to be between -1 and 1 to reduce outlier influence. This directly follows the method outlined by Yang et. al [https://www.nature.com/articles/s41467-025-64774-4]. For each cell type, a cumulative overlap plot is created by counting how many genes pass a threshold of correlation scores for the human dataset, the ferret dataset, and in both dataset, plotted all togehter on a single plot. Finally, the human and ferret scaled correlation socres are merged for the shared genes and classifies each gene as either `human-specific`, `ferret-specific`, or `well-associated` in both with a threshold of 0.7 as the gene correlation cutoff. A heatmap that compares these three groups of genes is created to highlight the percentage of marker genes that belong to a specific group.

#### `14_calculate_KEGG_pathways.R`

Back to an R environment, this script runs KEGG pathway enrichment analysis on the computational lineage driver genes that were pulled out from the `CellRank` steps. Using the `gost` enrichment function, we take a set of query genes and the custom background list generated earlier in the pipline and pull out the top KEGG pathway terms, sort by the p-values, and generate bubble plots of the top 25 most significant pathways shown first by p-value and then by recall. The scaled correlation score `.csv` files are read in and split by the correlation threshold of 0.7, then run with 3 groups of either all strongly correlated genes, positively correlated genes, or negatively correlated genes, and then creates these two plots for every combination for the 4 pseudotime lineages.

## Outputs

### `figures`

Output: A series of UMAPs, barplots, heatmaps, psuedotime computational lineage trajectories, CellRank terminal cell fate visualizations, and KEGG pathways detailing the integration, cell type validation, lineage drawing, and downstream validation of each of the steps in the pipeline.

### `rds_objects`

Output: All of the `Seurat` objects required to run each step in the sequence in `src`. Note that any of these scripts can be run in any preferred order, or all scripts can be run one after another to regenerate plots and downstream `Seurat` objects.

## How to Run

Each R script in the `src` directory can be run by simple language specific execution, either by `Rscript <##_analysis_step>.R` or `python3 <##_analysis_step>.py`.
